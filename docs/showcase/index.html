02 · 为何可以改变计算形态

顺序执行的任务，为何能改写为 GPU 上的一次数组运算

计算量并未减少，改变的是两层循环的顺序。

田块 × 天：依赖仅沿行方向，因此可以按列推进

作物模型中真正的顺序依赖只有一个方向：一块田的今天依赖它自身的昨天；不同田块、不同参数组之间不存在依赖。因此两层循环可以交换：不再是"对每块田，完整推进 3287 天"，而是"对每一天，让所有田块执行同一步计算"。内层这一步对十万块田是完全相同的算式，仅数值不同，正是 GPU 最擅长的形态：一条指令，十万个数。Fortran 无法交换顺序，原因不在速度，而在于每次运行被绑定在一个进程内：全局状态、按文件名读取输入、逐日写出文件。

Fortran
for 田块 in 十万块:
    for 天 in 3287 天:
        state = 日步(state)
    写 99 个文件
Agri-JAX
for 天 in 3287 天:             ← scan 把这层循环编译进图
    state[所有田块] = 日步(state[所有田块])
                               ← vmap 把"所有田块"变成数组的第一维
                               ← 一次数组运算，没有文件
03 · 过程函数

模型未变，改变的是过程的书写方式

每个过程仍是农学家熟悉的那条方程，只是读取与写入的内容全部写在函数签名上。

一个过程的形态：叶面积增长

此即 CERES 的叶面积扩展：ΔLAI = 展叶速率 × 今日积温 × 水分胁迫因子，仅在营养生长期发生。函数从"昨日状态"读取 LAI、生育期与土壤水，从"品种参数"读取展叶速率，从"今日天气"读取积温，计算今日 LAI 并写回状态。没有其它输入，也没有其它输出。这并非新模型，而是把原本散布于全局变量中的读写关系显式化。

04 · 三条规则，各自解决一个问题

编写过程函数只需遵守三条规则

1

纯函数。读的全在参数里，改的全在返回值里。

2

用 where 分支。不在状态量上写 Python if。

3

不写循环。土层、天数、样本的循环都由运行时接管。

规则一的原因：共享状态会互相覆盖

Fortran 模型中大量子程序通过 COMMON 块与 SAVE 变量共享状态：一个子程序修改的数值，另一个子程序在别处读取。单块田逐次运行时并无问题；十万块田同时运行，这些共享单元会互相覆盖，其中的数值归属无从判断。纯函数把每块田的状态置于其自身的一行，读取与写入均在签名上声明，十万行互不干扰。反向求导同样依赖这一点：链式法则必须沿明确的读写关系回溯。

规则二的原因：十万块田并不处于同一生育期

写作 if 生育期 == 营养生长 时，程序只能选择一条路径，而同一天的十万块田中，有的处于出苗期，有的已进入灌浆期。where 将两个分支同时计算，再按每块田自身的条件选取：营养生长期取增长值，其余取零。每块田获得各自的路径，整列仍是一次数组运算，梯度亦沿被选中的分支回传。

规则三的原因：循环由运行时承担

土壤剖面有 37 层，Fortran 以 for 循环自上而下逐层计算。同样的计算改写为对整个"层"维度的一次运算，37 层同时得出结果；十万块田排成列，便是一张 37 × 十万的表。时间循环由 scan 承担，样本循环由 vmap 承担，过程作者无需处理其中任何一层，过程代码中只保留方程本身。

05 · 一天如何由过程组成

模型 = 状态定义 + 一组有序的过程

七个过程依次执行，即为一日

每日从天气开始：计算潜在蒸散，分配截光，作物物候与生长，多作物水分竞争，土壤水再分配，最后写出诊断量。每个过程只访问其声明的字段，因此可以绘出这张数据流图，可以替换其中任一过程（以 Richards 替换桶模型，以神经网络替换气孔阻力），也可以逐个对照参考模型进行验证。

06 · 可微分带来的能力及其原因

一次反向传播，得到全部参数的梯度

以下每项能力均附有原理说明。进入视野后自动播放，可暂停、逐帧查看。

前向沿时间推进，反向沿同一路径回传

前向：状态从第 1 天推进至第 3287 天，逐日记录中间量（或按日设置检查点）。反向：自最后一天起，伴随量沿同一路径回传，经过每一天时累加当日对各参数的影响。回传完成后，全部参数的梯度同时得到，代价约为前向的数倍。参数灵敏度条为示意。

为何一次反向即可，而有限差分需要 P+1 次前向

有限差分需对每个参数分别扰动并各运行一次前向：30 个参数即 31 次九年模拟。反向模式沿同一张计算图将链式法则回溯一遍，所有参数的导数在一次回传中同时累积，代价约相当于数次前向，且与参数个数无关。

为何高维标定不再依赖随机采样

拉丁超立方在参数空间中布点后择优，维数升高时样本迅速稀疏。有了梯度，每一步都有明确方向，数十步即可抵达谷底；代价几乎不随维数增长，七个站点、百余参数的联合标定因此成为可能。底图为损失面，颜色越绿数值越低（示意）。

为何能够判定哪些参数不可辨识

损失面在某些方向陡峭，在另一些方向平坦。平坦方向即数据无法约束的参数组合，例如仅有 ET 观测时的 Ksat 与 λ。Fisher 信息矩阵等于雅可比矩阵的转置与自身之积，一次反向传播即可求得，其特征值谱直接给出可辨识方向的数量（示意）。

为何采用一千条短链而非四条长链

NUTS 的每一步都需要梯度，单条链是串行的，每步有固定延迟。而在 GPU 上，四条链与一千条链在 vmap 中耗时相同。因此合理的形态是大量短链同时采样：总样本数不变，墙钟时间由数十小时降至一小时量级。

为何能将神经网络嵌入机理模型并端到端训练

只要整条计算链可微，损失对网络权重的梯度便能穿过其后的机理过程回传。于是可以仅将最不确定的那个过程替换为小型网络，以通量塔 ET 端到端训练，其余过程仍保持守恒与可解释性。

为何能够回答"哪场降雨决定了产量"

反向传播不仅对参数求导，对每日降雨、初始含水量等输入同样适用。伴随量沿生长季回传，每一天降雨对最终产量的边际贡献同时得到，一条曲线即可回答归因问题（示意）。
