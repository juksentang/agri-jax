AGRI-JAX

十万块田，同一天，一起算；
算完还能求导。

田块尺度的作物–土壤模型，写成可微分、可批量的形式。右侧的矩阵是全页唯一的图：行是田块，列是天。

01

十万块田，Fortran 一块一块跑完，JAX 一天一天一起走

  1. 逐行填：一个核一次只跑一块田，32 个核同时开工，屏幕时间等于真实时间
  2. 加速到跑完：真实 20.8 小时，磁盘上堆到 80 GB、990 万个文件
  3. 换走法：整列同亮，每一步全部田块前进一天，显存 8 GB，磁盘写入 0
  4. 列扫到底：3287 天，真实 82 秒

同一个矩阵、同一比例尺，只是走法不同。时钟、磁盘、显存为实测；格子颜色为示意。

02

顺序只沿着行，所以可以按列推进

  1. 每一格只依赖同一行左边的一格：今天只依赖自己的昨天
  2. 行与行之间没有箭头：这块田的水不会流进另一块田的方程
  3. 于是交换两层循环：外层按天，内层对所有行做同一件事
  4. 一列 = 十万个数上的同一条指令，正是 GPU 擅长的形状

Fortran 做不到不是因为慢，而是每次运行被全局状态和逐文件读写绑在一个进程里，换不了循环顺序。

03

一天 = 七个过程接力；过程只是方程，读什么写什么写在签名上

  1. 把一列抽出来：天气、潜在蒸散、截光、作物、争水、土壤水、诊断依次执行，虚线是各自读写的字段
  2. 放大"作物"：叶面积增长 = 展叶速率 × 积温 × 水分胁迫，只在营养生长期发生
  3. 规则一，纯函数：共享格子被两块田同时写会撞车，所以状态每田一行
  4. 规则二，用 where 分支：同一天各田处于不同生育期，两条都算、逐行挑
  5. 规则三，不写循环：37 层土壤整列一次算完，时间与样本的循环交给运行时
04

沿同一条路倒着走一遍，全部参数、全部输入的导数一次得到

  1. 前向：列从左到右扫一遍，每一天的状态留下来
  2. 反向：从最后一天往回扫，经过每一列，参数的导数各累积一点
  3. 代价：有限差分要 31 次前向；反向只要 1 次前向加 1 次反向
  4. 可辨识性：损失谷平的方向是数据分不开的参数组合，一眼看出
  5. 归因：对每一天的降雨求导，哪场雨决定收成，峰在吐丝期
  6. 多链：行从"田块"换成"链"，一千条短链与四条长链花一样的时间
  7. 嵌入网络：把气孔阻力换成小网络，梯度穿过机理过程流进权重

撒点标定的样本数随维数指数增长，梯度法几乎不增长。参数柱、损失谷、归因曲线为示意。
