01Two modes4 frames

A hundred thousand fields: Fortran runs them one by one, JAX moves them all forward one day at a time

  1. 1.1Row by row, taking a 32-core workstation: each core runs one field at a time, 32 cores work in parallel, and screen time equals estimated time
  2. 1.2Fast-forward to completion: an estimated 20.8 hours on a 32-core workstation at 24 s per run, with 80 GB and 9.9 million files piled up on disk
  3. 1.3Change the order: a whole column lights up at once and every field advances one day per step; 8 GB of GPU memory, zero bytes written to disk
  4. 1.4The column sweeps to the end: 3287 days in a measured 82 seconds (computational skeleton)

02Why it works4 frames

Sequential order runs only along the rows, so the computation can advance column by column

  1. 2.1Each cell depends only on the cell to its left in the same row: today depends only on its own yesterday
  2. 2.2There are no arrows between rows: the water of one field never enters the equations of another
  3. 2.3So the two loops can be swapped: the outer loop runs over days, the inner applies the same operation to every row
  4. 2.4One column = one instruction over a hundred thousand numbers, exactly the shape a GPU is built for

Existing Fortran implementations do not natively support array-style batch execution: global state and per-run file I/O bind each simulation to a single process. This is a property of the implementation, not of the language.

03What happens in one column5 frames

One day = a relay of seven processes; a process is only equations, and what it reads and writes is stated in its signature

  1. 3.1Extract one column: weather, potential evapotranspiration, light interception, crop, water competition, soil water and diagnostics run in sequence; the right side shows the fields each one reads and writes
  2. 3.2Zoom in on “Crop”: leaf-area growth = leaf appearance rate × thermal time × water stress, occurring only during vegetative growth
  3. 3.3Rule one, pure functions: a shared cell written by two fields at once is a collision, so the state holds one row per field
  4. 3.4Rule two, branch with where: on the same day the fields are at different growth stages, so both branches are computed and each row picks its own
  5. 3.5Rule three, no loops: all 37 soil layers are computed in one pass; the loops over time and samples are left to the runtime
04Gradients9 frames

Walk the same path once in reverse, and obtain the derivatives with respect to every parameter and every input in a single pass

  1. 4.1Forward: the column sweeps from left to right, and the state of every day is kept
  2. 4.2Reverse: sweep back from the last day; at every column, each parameter’s derivative accumulates a little
  3. 4.3Cost: finite differences need 31 forward runs; reverse mode needs only 1 forward plus 1 reverse pass
  4. 4.4Identifiability: the flat directions of the loss valley are parameter combinations the data cannot separate, visible at a glance
  5. 4.5Attribution: differentiate with respect to each day’s rainfall to see which rain decides the yield; the peak falls at silking
  6. 4.6Sampling versus descent: Latin hypercube sampling spends one forward run per point and learns no direction; every gradient step points downhill. Agri-JAX batches both: sample 10⁵ points first, then descend in parallel from the best few
  7. 4.7Many chains to be tested: the rows change from “fields” to “chains”; a step with a thousand chains takes the same time as a step with four. Whether many short chains can replace a few long ones must be compared at equal effective sample size (ESS)
  8. 4.8SVI to be tested: fit a distribution q to the posterior; each step draws a large batch of parameter sets, runs one batched forward and reverse pass, and updates the mean and covariance of q. The result approximates the whole posterior, not just a best point
  9. 4.9Embedded network: replace stomatal resistance with a small network; the gradient passes through the process model into its weights

The relative cost of sampling-based calibration and gradient methods depends on the objective, the parameter correlations and the algorithm; a gradient gives a descent direction at every step, at a cost independent of the number of parameters. The many-chains frame is a hypothesis to be tested: MCMC samples are autocorrelated, so inference efficiency must be compared at equal effective sample size (ESS); raw sample counts are not a measure of inference quality. Parameter bars, loss valley, attribution curve, sampling and descent paths and the SVI animation are illustrative; variational approximations can understate posterior variance and must be checked against MCMC.

05Your hardwareestimator

One GPU in your lab is enough

The RTX 4060 Laptop is measured (computational skeleton); JAX on the CPU is measured on an AMD EPYC 9654 on rorqual (one single-threaded process per core, same core count as Fortran; beyond 32 cores scaled linearly); other GPUs are extrapolated from the H100 measurements using the slower of memory bandwidth and double-precision throughput, calibrated on the 4060 measurement (consumer GPUs run float64 at 1/64 of float32 speed); Fortran is estimated as 24 s per run divided by the number of cores (20.8 h on a 32-core workstation; the cluster batch as actually run took about 10 h, job array with 8 tasks per node, including queueing and I/O); the full model is already discounted by a factor of 3.
